# A three-minute FullGo product demonstration

[Back to the case study](../README.md)

This is a demonstration outline, not a claim that a video has been recorded. Use a synthetic adult account and fictional athlete. Show only behavior that currently works in the demonstrated build.

## 0:00–0:30 — Start with the problem

“Parents make decisions about teams, training, recovery, and competing commitments. FullGo is intended to help them gain perspective without turning their child's sports experience into a scorecard.”

Show the current Guide entry point. Identify the intended user as the parent or guardian.

## 0:30–1:15 — Demonstrate immediate value

Use a fictional question: “My child enjoys the current team, but we're being encouraged to add another. How should we think about it?”

Show the response and explain the intended behavior: make tradeoffs visible, acknowledge uncertainty, and leave the decision with the family. Do not imply that the output is medical advice or that it predicts the child's future.

## 1:15–2:00 — Explain memory and permission

If available in the current build, show a parent-approved memory proposal and its attribution. Explain the distinction between a conversation and an approved durable fact. If a step is incomplete, name that limitation rather than simulate it as functioning software.

## 2:00–2:30 — Connect guidance to Journey

Show a fictional saved moment or photo. Explain why a meaningful family story is different from an exhaustive activity feed.

## 2:30–3:00 — Close with delivery and learning

“I owned the product direction, workflows, requirements, and acceptance review, using AI-assisted development and managed platforms to build and iterate. The web experience is live, and the iOS build reached approved TestFlight distribution. My next question is whether families return because the perspective is useful—not because the app asks them to maintain a streak.”
